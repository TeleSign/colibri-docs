  ## How to use it

  1. Install the package:
      ```bash
      npm install @colibri/colibri-components
      ```

  2. Import the dependencies:
      ```ts
      import { registerColibriComponents, registerColibriComponents, ColSearchBar } from '@telesign/colibri';
      import '@telesign/colibri/styles/styles.css';
      ```

  3. Register the components:
      ```typescript
      // Option 1: Register specific components
      registerColibriComponents([ColSearchBar]);

      // Option 2: Register all Colibri components
      registerAllComponents();
      ```    

  4. Use it in your HTML:
      ```html
      <col-search-bar placeholder="Search..." variant="static"></col-search-bar>
      ```

  ## When to use it

  Use the `col-search-bar` when you need a lightweight, interactive search input. Ideal use cases include:

  - **Search functionality** in toolbars or filters.
  - **Expandable search inputs** that save space by default.
  - **Forms or modals** that require compact input for search.

  ## Event handling

  The `col-search-bar` component emits a custom event named `search-input` instead of the native `input` event. This allows you to listen specifically for search-related input.

  ```ts
  <col-search-bar
    placeholder="Search..."
    @search-input=${(e) => console.log('Search value:', e.detail.value)}
  ></col-search-bar>
  ```

  ## Accessibility

  <div>
    The `col-search-bar` component is built with accessibility in mind, ensuring a seamless experience for all users, including those using screen readers and other assistive technologies.
  </div>

  - **Labeling:** You can pass a visible label or use `aria-label` to ensure the input is correctly announced by screen readers.
  - **Unique IDs:** Each instance automatically generates unique internal IDs, or you can provide a custom `id` for better control and accessibility.
  - **ID Mapping:**
    - Custom `id` values are used as the base for internal elements like labels, error messages, and helpers (e.g., `search-id-label`, `search-id-helper`).
  - **Keyboard Support:** Fully keyboard-navigable using `Tab`, `Shift+Tab`, and other standard keys.
  - **ARIA Attributes:**
    - Supports `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-required`, and `aria-invalid`.
    - `aria-describedby` links the input to helper or error text when applicable.
    - The clear button is accessible and includes `aria-controls` when needed.
  - **Announced States:** States like `disabled`, `readonly`, and `error` are properly conveyed to assistive technologies.
  - **Best Practices:**
    - Always provide a descriptive label or `aria-label`.
    - Use `helper` text to guide users when needed.
    - Assign a meaningful `id` if integrating with forms or testing frameworks.
    - Keep error messages clear and concise for screen reader users.
