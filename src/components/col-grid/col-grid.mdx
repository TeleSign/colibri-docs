    <Subtitle>Component vs Utility Approach</Subtitle>
    The Colibri Design System offers two approaches for creating grid layouts:

    - **Components** (`col-grid`, `col-grid-item`) - Declarative, type-safe, with built-in validation
    - **Utilities** (CSS classes like `.col-grid-cols-3`) - Direct styling, maximum flexibility

    This documentation focuses on the component approach. For utility classes, see the Foundation Grid documentation linked above.

    ## How to use it
    1. Install the packages:
        ```bash
        npm install @telesign/colibri
        ```
    2. Import the dependencies:
        ```typescript
        import { registerColibriComponents, registerAllComponents, ColGrid, ColGridItem } from '@telesign/colibri';
        import '@telesign/colibri/styles/styles.css';
        ```
    3. Register the web components:
        ```typescript
        // Option 1: Register specific components
        registerColibriComponents([ColGrid, ColGridItem]);

        // Option 2: Register all Colibri components
        registerAllComponents();
        ```
    4. Use it in your HTML:
        ```html
        <!-- Basic 3-column grid -->
        <col-grid cols="3" gap="m">
          <col-grid-item>Item 1</col-grid-item>
          <col-grid-item>Item 2</col-grid-item>
          <col-grid-item>Item 3</col-grid-item>
        </col-grid>

        <!-- Responsive grid with column spanning -->
        <col-grid cols="1" sm="2" md="3" lg="4" gap="l">
          <col-grid-item col-span="1" sm="2" md="3" lg="4">
            Full width header
          </col-grid-item>
          <col-grid-item>Card 1</col-grid-item>
          <col-grid-item>Card 2</col-grid-item>
          <col-grid-item>Card 3</col-grid-item>
          <col-grid-item>Card 4</col-grid-item>
        </col-grid>

        <!-- Grid with named areas -->
        <col-grid areas="header-sidebar-main" gap="m">
          <col-grid-item area="header">Header Content</col-grid-item>
          <col-grid-item area="sidebar">Sidebar Content</col-grid-item>
          <col-grid-item area="main">Main Content</col-grid-item>
        </col-grid>
        ```

    ## When to use it
    The Grid system provides flexible layout solutions for various design patterns and use cases:

    ### `col-grid` (Container)
    Use the `col-grid` component for creating layout containers with:

    - **Product grids** - E-commerce listings, image galleries, card layouts
    - **Dashboard layouts** - Multi-panel interfaces with metrics, charts, and widgets
    - **Content layouts** - Article grids, blog post listings, news feeds
    - **Form layouts** - Multi-column forms with grouped fields
    - **Navigation layouts** - Menu systems, tab containers, breadcrumb structures
    - **Responsive page layouts** - Headers, sidebars, main content areas, footers
    - **Auto-fit content** - Dynamic layouts that adapt to available space
    - **Semantic areas** - Named grid regions for consistent page structure

    ### `col-grid-item` (Items)
    Use `col-grid-item` components for positioning content within grids:

    - **Spanning elements** - Headers, footers, or featured content that spans multiple columns/rows
    - **Responsive positioning** - Items that change size or position across breakpoints
    - **Named area placement** - Content assigned to specific semantic regions
    - **Flexible sizing** - Items that adapt to grid constraints while maintaining proportions
    - **Accessibility labeling** - Content with specific ARIA labels for screen readers

    ### Best Practices

    **Choose `col-grid` when you need:**
    - Type-safe grid properties with built-in validation
    - Responsive design with breakpoint-specific configurations
    - Semantic grid areas for consistent layouts
    - Component-based architecture with clear APIs

    **Consider utility classes when you need:**
    - Maximum performance with minimal JavaScript overhead
    - Direct control over CSS classes
    - Integration with existing utility-first CSS frameworks
    - Static layouts that don't require dynamic property changes

    **Accessibility considerations:**
    - Use `aria-label` or `aria-labelledby` on grid containers for screen readers
    - Ensure logical tab order matches visual layout
    - Consider reading order when using grid areas or spanning elements
    - Test with keyboard navigation and screen readers

    **Performance recommendations:**
    - Use `auto-fit` for dynamic layouts instead of media queries when possible
    - Prefer semantic grid areas over complex spanning for better maintainability
    - Consider CSS Grid native features for simple layouts
    - Use gap properties instead of margin/padding for consistent spacing

    ### Grid areas

    These are the most common templates and layouts provided for convenience, but they are not exhaustive and can be customized or overwritten with custom CSS properties to meet your specific design needs.

    #### Customizing Grid Areas

    You can override the default grid template areas by setting the `--col-grid-template-areas` CSS custom property:

    ```css
    .my-custom-grid {
      --col-grid-template-areas:
        "header header header"
        "sidebar main aside"
        "footer footer footer";
    }
    ```

    For more complex layouts, you can also customize other grid properties:

    ```css
    .my-advanced-grid {
      --col-grid-template-areas:
        "nav nav nav nav"
        "sidebar content content aside"
        "sidebar content content aside"
        "footer footer footer footer";
      --col-grid-template-columns: 200px 1fr 1fr 150px;
      --col-grid-template-rows: 60px 1fr 1fr 80px;
      --col-grid-gap: 1rem;
    }
    ```

    Then assign grid items to their respective areas using the `area` attribute:

    ```html
    <col-grid class="my-custom-grid">
      <col-grid-item area="nav">Navigation</col-grid-item>
      <col-grid-item area="sidebar">Sidebar</col-grid-item>
      <col-grid-item area="content">Main Content</col-grid-item>
      <col-grid-item area="aside">Aside</col-grid-item>
      <col-grid-item area="footer">Footer</col-grid-item>
    </col-grid>
    ```

    Grid areas work with two different attributes on two different components:

    **1. Layout Templates (`areas` attribute on `col-grid`)**

    Use the `areas` attribute on the grid container to define the overall layout structure:

| Template Name | CSS Grid Areas Value | Description |
|---------------|---------------------|-------------|
| `header-main` | `"header" "main"` | Simple header and main content (stacked vertically) |
| `main-sidebar` | `"main sidebar"` | Two-column layout (main content left, sidebar right) |
| `header-content` | `"header header" "content content"` | Header with full-width content below |
| `header-toolbar-content` | `"header header" "toolbar toolbar" "content content"` | Header, toolbar, and content sections |
| `sidebar-main` | `"sidebar main"` | Sidebar left, main content right |
| `header-sidebar-main` | `"header header" "sidebar main"` | Classic three-section layout (header full width, sidebar + main below) |
| `toolbar-table` | `"toolbar toolbar" "table table"` | Toolbar above table/list content |
| `dashboard-simple` | `"nav header" "nav main"` | Navigation sidebar with header and main content |
| `dashboard-complex` | `"nav header header" "nav main aside" "nav footer footer"` | Full dashboard with nav, header, main, aside, and footer |
| `article-layout` | `"header header" "content sidebar" "footer footer"` | Article with header, content + sidebar, and footer |
| `form-layout` | `"title title" "form sidebar" "actions actions"` | Form with title, form + sidebar, and actions |
| `app-layout` | `"header header header" "sidebar main aside" "footer footer footer"` | Complete application layout with all regions |

    **2. Area Assignment (`area` attribute on `col-grid-item`)**

    Use the `area` attribute on individual grid items to assign them to specific regions:

| Area Name | CSS Grid Area Value | Description |
|-----------|-------------------|-------------|
| `header` | `header` | Page or section header content |
| `main` | `main` | Primary content area |
| `sidebar` | `sidebar` | Secondary navigation or complementary content |
| `content` | `content` | Main article or content body |
| `toolbar` | `toolbar` | Action buttons or tools |
| `table` | `table` | Data tables or lists |
| `footer` | `footer` | Page or section footer content |
| `nav` | `nav` | Navigation menus |
| `aside` | `aside` | Complementary content or widgets |
| `title` | `title` | Section titles or headings |
| `form` | `form` | Form fields and inputs |
| `actions` | `actions` | Action buttons (save, cancel, etc.) |
